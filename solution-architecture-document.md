# Документ Архітектури Рішення - Cool Sip CMS

## 1. Огляд

### 1.1 Призначення
Цей документ описує архітектурний дизайн Cool Sip CMS, платформи електронної комерції, що спеціалізується на слабоалкогольних напоях. Платформа дозволяє користувачам переглядати продукти за категоріями, додавати товари до кошика, керувати своїми адресами, розміщувати замовлення, а також надає адміністративні можливості для управління продуктами, категоріями та замовленнями.

### 1.2 Обсяг
Документ описує високорівневу архітектуру, шаблони проектування, структуру компонентів, потік даних та технічні міркування для системи Cool Sip CMS.

## 2. Архітектурний підхід

### 2.1 Архітектурний стиль
Додаток реалізує архітектурний шаблон Model-View-Controller (MVC) з такими компонентами:
- **Моделі**: Інкапсулюють дані та бізнес-логіку
- **Представлення**: Відповідають за презентацію та інтерфейс користувача
- **Контролери**: Обробляють запити, взаємодіють з моделями та вибирають відповідні представлення

### 2.2 Ключові шаблони проектування
- **Шаблон Одинак (Singleton)**: Використовується в класі Core для забезпечення єдиного екземпляра, що керує станом додатка
- **Шаблон Front Controller**: Реалізований через вхідну точку index.php та клас Core для маршрутизації запитів
- **Шаблон Репозиторій**: Абстрагований у класах моделей для відокремлення логіки доступу до даних
- **Шаблон Template**: Використовується в системі рендерингу представлень

## 3. Структура компонентів

### 3.1 Основні компоненти
- **Система ядра**
  - `Core.php`: Головний контролер додатка та точка входу
  - `Controller.php`: Базовий клас контролера із загальними функціями
  - `DB.php`: Рівень абстракції бази даних
  - `Template.php`: Система рендерингу представлень
  - `Error.php`: Обробка помилок
  - `Utils.php`: Службові функції

### 3.2 Контролери
- `MainController`: Обробляє головну сторінку та сторінки помилок
- `ProductController`: Керує списками продуктів, деталями, додаванням/редагуванням/видаленням продуктів
- `CategoryController`: Керує списками категорій, деталями, додаванням/редагуванням/видаленням категорій
- `CartController`: Обробляє функціональність кошика
- `UserController`: Керує аутентифікацією користувачів, реєстрацією, профілями
- `AddressController`: Керує адресами доставки користувачів
- `AdminController`: Надає функціональність для адміністраторів

### 3.3 Моделі
- `Product`: Дані та операції з продуктами
- `Category`: Дані та операції з категоріями
- `User`: Аутентифікація користувачів та управління профілями
- `Cart`: Функціональність кошика
- `Order`: Обробка та управління замовленнями
- `Address`: Управління адресами доставки

### 3.4 Представлення
- Шаблон макету (`views/layout.php`)
- Шаблони представлень, організовані за назвою контролера
- Спільні компоненти інтерфейсу

### 3.5 Фронтенд компоненти
- CSS-фреймворк Bootstrap для адаптивного дизайну
- Власні стилі CSS
- JavaScript для інтерактивних елементів
- CKEditor для редагування форматованого тексту в адміністративних розділах

## 4. Потік даних

### 4.1 Обробка запитів
1. Усі запити проходять через `index.php`
2. Клас `Core` ініціалізується та аналізує URL для визначення контролера та дії
3. Запитаний контролер та метод викликаються з параметрами
4. Контролер обробляє запит, взаємодіє з моделями
5. Представлення рендеряться з даними та надсилаються клієнту

### 4.2 Потік аутентифікації
1. Користувачі реєструються через `UserController::registerAction()`
2. Вхід обробляється через `UserController::loginAction()`
3. Статус аутентифікації користувача підтримується в сесії
4. Контроль доступу реалізовано в контролерах (наприклад, `User::isAdmin()`)

### 4.3 Потік покупок
1. Користувачі переглядають продукти та категорії
2. Додають продукти до кошика (`Cart::addProduct()`)
3. Переглядають вміст кошика та оновлюють кількість товарів
4. Процес оформлення замовлення через `CartController::informationAction()`
5. Розміщення замовлення через `Order::makeOrder()`
6. Підтвердження замовлення з унікальним ідентифікатором

## 5. Міркування щодо безпеки

### 5.1 Аутентифікація та авторизація
- Хешування паролів через MD5 (Примітка: Це слід оновити до сильнішого алгоритму, як bcrypt)
- Аутентифікація на основі сесій
- Контроль доступу на основі ролей (звичайні користувачі та адміністратори)

### 5.2 Валідація введення
- Валідація даних форм реалізована в контролерах
- Серверна валідація перед операціями з базою даних
- Запобігання XSS через фільтрацію введення та екранування

### 5.3 Проблеми безпеки
- **Поточна проблема**: Хешування паролів MD5 недостатньо за сучасними стандартами
- **Рекомендація**: Оновити до функції PHP password_hash() з bcrypt або Argon2

## 6. Обробка помилок

### 6.1 Підхід

- Відповіді на помилки на основі кодів статусу HTTP
- Зручні для користувача сторінки помилок для поширених помилок (404, 403)

### 6.2 Журналювання

- **Рекомендація**: Запровадити комплексну систему журналювання

## 7. Залежності

### 7.1 Вимоги до сервера
- PHP 7.x або вище
- База даних MySQL
- Веб-сервер Apache з mod_rewrite або Nginx

### 7.2 Зовнішні бібліотеки
- CSS-фреймворк Bootstrap
- CKEditor
- jQuery

## 8. Дизайн бази даних

### 8.1 Ключові таблиці
- `user`: Облікові записи користувачів та аутентифікація
- `product`: Інформація про продукти
- `category`: Категорії продуктів
- `address`: Адреси доставки користувачів
- `custom`: Інформація про замовлення

### 8.2 Ключові відносини
- Продукти належать до Категорій (багато-до-одного)
- Користувачі мають Адреси (один-до-багатьох)
- Користувачі розміщують Замовлення (один-до-багатьох)
- Замовлення містять Продукти (багато-до-багатьох)

## 11. Висновок

Система Cool Sip CMS реалізує стандартну архітектуру MVC з чітким розділенням відповідальності. Система надає міцну основу для платформи електронної комерції з функціями як для клієнтів, так і для адміністрування. Для майбутнього розвитку рекомендовано ряд покращень безпеки та продуктивності.
